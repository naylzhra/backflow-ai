Refactor the entire visual design of the existing BackFlow AI web app into a mature, intentional B2B logistics operations product.

Keep the existing product, information architecture, navigation, functionality, and core user flows. Only refactor the visual system and layout.

DESIGN DIRECTION

Make it feel like real software used daily by dispatchers and fleet managers in an Indonesian logistics company.

Visual character:
- precise
- operational
- trustworthy
- efficient
- slightly utilitarian
- desktop-first
- information-dense where useful

Avoid making it feel like:
- generic SaaS template
- AI startup dashboard
- futuristic AI product
- marketing landing page
- design showcase

AI should be communicated through the matching functionality and data, NOT through decorative AI visuals.

VISUAL SYSTEM

Use:
- dark navy / charcoal navigation
- very light neutral gray background
- white surfaces
- teal for matching, route intelligence, and successful states
- orange ONLY for the primary action
- restrained gray scale
- one primary sans-serif typeface
- consistent 8px spacing system
- consistent typography, input heights, buttons, radii, and alignment across all pages

Use solid colors. Avoid gradients.

Reduce visual decoration and let typography, spacing, data hierarchy, and route visualization create the visual identity.

CARDS & CONTAINERS

Do NOT put every section inside a card.

Avoid:
- card inside card
- excessive rounded containers
- floating cards everywhere
- excessive borders/outlines
- excessive shadows
- excessive corner rounding

Use whitespace, alignment, subtle background changes, and occasional dividers to separate sections.

Interactive inputs/buttons may still use borders.

HEADINGS

Section headings must be plain typography.

NEVER use:
- vertical colored bars beside headings
- colored accent lines attached to headings
- decorative underlines
- random colored words
- gradient text
- decorative icons beside every heading
- eyebrow labels above every section

For example:

Efisiensi Backhaul

Matching dengan Penghematan Terbesar

NOT:

▌ Efisiensi Backhaul

▌ Matching dengan Penghematan Terbesar

Do not invent decorative heading components.

A section title is simply a title.

TYPOGRAPHY

Use one consistent sans-serif typeface.

Create a disciplined hierarchy:
Page title → Section title → Body → Supporting text → Metadata.

Do not overuse bold, italics, uppercase text, or giant numbers.

Only genuinely important metrics such as match score and estimated savings should be visually dominant.

COMPONENT DISCIPLINE

Use a small reusable design vocabulary:
- page header
- section heading
- input
- dropdown
- button
- status
- metric
- data row
- table
- route visualization
- recommendation block
- empty state

Do not create a new decorative component for every section.

Do not turn normal metadata into pills or badges.

Use badges only for meaningful states such as:
- 92% cocok
- Diambil
- warning
- validation

LOGISTICS VISUAL IDENTITY

Build the visual identity around:

ROUTE
FLOW
DIRECTION
MOVEMENT
BACKHAUL

Use route lines, nodes, directional markers, truck/cargo icons, distance, time, and location relationships as functional visual language.

Route visualization should feel like operational logistics software, not decorative infographic art.

Avoid generic:
- sparkles
- magic wand
- robots
- neural networks
- holographic graphics
- abstract AI waves
- glowing effects
- futuristic illustrations
- generic AI imagery

LAYOUT

Use a consistent grid and alignment system across Dashboard, Cari Muatan, Riwayat, and Laporan.

Do not make every page centered or symmetrical.

Use desktop width effectively with:
- meaningful columns
- horizontal metadata
- compact rows
- structured tables
- route strips

Do not create huge hero sections or excessive empty space.

Do not add decorative elements just because an area looks empty.

INPUT PAGE

Keep "Cari Muatan" operational and compact.

Group related fields through typography and spacing rather than multiple cards.

Prioritize:
Rute → Detail Perjalanan → Primary CTA.

RECOMMENDATION PAGE

Make the recommendation the main decision point.

Prioritize:
92% cocok
→ route visualization
→ order & cargo details
→ estimated savings
→ actions

Do not make it look like a futuristic AI result card.

DASHBOARD

Avoid the generic:
KPI cards + charts + activity cards.

Make it an operational workspace answering:

"Apa yang perlu saya lakukan sekarang?"

Use compact operational lists and route-based activity.

RIWAYAT

Use a proper data table rather than card-based rows.

Example:

Tanggal | Rute | Order | Muatan | Match | Penghematan | Status | Aksi

Use alignment and subtle row separators.

LAPORAN

Keep it restrained.

Prioritize:
- total matching berhasil
- truk terisi kembali
- estimasi penghematan
- rata-rata penghematan
- one meaningful savings visualization
- highest-value matches

Do not turn it into a complex BI dashboard.

AVOID ALL COMMON AI-GENERATED UI PATTERNS

No:
- random accent colors
- decorative vertical heading bars
- excessive pills
- excessive cards
- excessive outlines
- excessive shadows
- excessive rounded corners
- gradients
- glassmorphism
- glowing effects
- oversized icons
- decorative illustrations
- generic AI terminology
- marketing copy
- excessive tooltips
- decorative charts
- giant hero sections
- repetitive card grids
- perfectly symmetrical layouts everywhere
- center-aligned content everywhere
- fake statistics
- unnecessary visual hierarchy

FINAL PRINCIPLE

Make the interface feel designed, not generated.

Premium should come from:
precision + consistency + hierarchy + information architecture

NOT:
decoration + gradients + cards + badges + AI visual effects.

The result should feel like:

"professional logistics software that happens to use AI"

not:

"an AI dashboard template."
